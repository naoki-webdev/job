# アーキテクチャ

## アプリケーションの流れ

求人票本文を受け取り、ルールベースまたはAIで構造化します。求人として保存すると、ユーザーごとのスコア設定と評価マスタを使ってスコアを計算し、一覧・CSV出力・サマリー・ランキングに反映します。

```text
求人票本文
  → JobDrafts::Builder
  → RuleBasedParser または AiExtractor
  → ユーザー別マスタとの照合
  → 下書き・判定結果
  → Job
  → JobsQuery / JobSerializer / JobsCsvExport
```

## Railsの責務

- `ApplicationController`: 認証、閲覧専用ユーザーの書き込み拒否、クロスオリジン書き込みの拒否
- `JobsController`: 求人CRUDと、関連する操作ログの記録
- `JobsQuery`: キーワード検索、絞り込み、ソート、ページネーション
- `JobSerializer`: APIレスポンスの整形
- `JobsCsvExport`: CSV生成とFormula Injectionの無害化
- `JobDrafts::Builder`: 求人票の構造化、AI出力の検証、評価マスタに基づく判定

スコア設定またはスコア付きマスタの重みを更新すると、対象ユーザーの求人スコアを同期的に再計算してからレスポンスを返します。更新直後のランキングが古いスコアを参照しないためです。

## ユーザー分離と認証

求人、スコア設定、職種、勤務地、技術スタック、評価キーワード、面接質問はユーザーに紐づきます。APIは `current_user` の関連からレコードを取得し、`Job` モデルでも職種・勤務地・技術スタックの所有者が求人の所有者と一致することを検証します。

認証にはDBセッションを使います。ランダムなセッショントークンそのものは保存せず、SHA-256 digestを保存します。CookieはHttpOnlyで、ログアウト時には対応するセッションレコードを削除します。

公開デモの読み取り専用ユーザーは、UIだけでなく書き込み系APIでも拒否します。

## AI求人票取り込み

`POST /api/job_drafts` は次の入力を受け取ります。

```json
{
  "job_draft": {
    "mode": "rule",
    "url": "https://example.com/jobs/123",
    "text": "求人票本文"
  }
}
```

`mode` に `ai` を指定できるのは `ai_enabled` が有効なユーザーだけです。それ以外はサーバー側でルールベースへ切り替えます。本文は8,000文字まで、取り込みAPIはユーザー単位で5分間に20回までです。

AI出力はそのまま採用しません。技術スタック・勤務地・加点・減点・質問をユーザー登録済みのマスタと照合し、推定スコアは0〜100に制限します。AIの応答が意味のある構造を持たない場合や失敗した場合は、ルールベースへフォールバックします。

## ファイル添付

会社ロゴはActive Storageで扱います。画像のMIME typeと5MB上限を検証し、通常の求人更新はJSON、画像を含む更新だけを`multipart/form-data`で送信します。本番ではローカルfilesystemではなく、S3互換ストレージへ保存します。
